## Update guide

### 1. Check the installed firmware version

The device shows as "Canimal Systems CAN-USB". Firmware before 0.1.2 shows "Canimal Cheetah".

On Linux:

```
lsusb -v -d 1d50:606f | grep bcdDevice
```

`bcdDevice` holds the major and minor version, so 1.2.0 shows as 1.02.

On macOS, open System Information, select USB, select CAN-USB, and read "USB Product Version". It is shown in hex: `0x0001` is 0.1 and `0x0102` is 1.2.
### 2. Verify the download

Compare the output with the SHA-256 on this page. On Linux:

```
sha256sum canimal-can-usb-<version>.signed.bin
```

On macOS:

```
shasum -a 256 canimal-can-usb-<version>.signed.bin
```

### 3. Flash the firmware

Install `dfu-util`, then run:

```
dfu-util -d 1d50:606f,1d50:0005 -a 1 -R -D canimal-can-usb-<version>.signed.bin
```

If several boards are attached, add `-S <serial>` to select one.

Do not use `dfu-util -e`. It leaves the board in DFU mode.

### 4. Confirm the new version

The board restarts and re-enumerates, which takes about 10 seconds. Repeat step 1 and check the version.

From firmware 0.1.3, an update over USB is a trial. Keep the board plugged in for 30 seconds after the update finishes. If it is unplugged sooner, the previous firmware comes back at the next power-up. Update again to retry.

The USB version shows major.minor only (1.2.0 shows as 1.02), so it changes for major and minor updates but not for patch updates, for example 0.1.2 to 0.1.3. Updating from firmware older than 0.1.2 also changes the device name from "Canimal Cheetah" to "Canimal Systems CAN-USB".

On macOS, you may be asked to "Allow" the accessory after an update.

### Going back to 0.1.2 or older

From 0.1.3 or newer, flash the older firmware twice in a row, without unplugging the board in between. Firmware 0.1.2 and older can't make itself permanent, so a single flash is undone at the next power-up. The second flash, made while the older firmware is running, stays.

### If something goes wrong

If the download is interrupted, the board stays in update mode and keeps its current firmware. To finish the update, run the same `dfu-util` command again. To go back to the firmware it had, unplug the board and plug it back in. If the board doesn't come back either way, contact support.

## Custom firmware

Releases are signed with the public MCUboot development key on purpose, so you can build and flash your own firmware. From 0.1.3 on, an update is undone at the next power-up unless the new firmware confirms itself. Firmware built from the 0.1.3 source or newer does this the same way as a release. Other firmware has to mark itself as confirmed with MCUboot.
